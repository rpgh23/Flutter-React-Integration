Why two builds?
The Release Flutter engine (AOT compiled) requires an AOT App.xcframework device slice — only produced by a Release build.
The Simulator needs a Debug App.xcframework slice (contains kernel_blob.bin) — only produced by a Debug build.
We combine them into one mixed App.xcframework.
Detailed Steps with Commands
1
Build Debug Flutter Frameworks (Simulator slice)
REQUIRED

This produces the Debug App.xcframework simulator slice with kernel_blob.bin. Only needed when Flutter code changes.

# [1/9] Build Debug Flutter frameworks
echo "=== [1/9] Building Debug Flutter frameworks ==="

cd /Users/salespanda/rahul_work_space/sp-sdk/flutter-new-sdk

flutter build ios-framework \
  --no-release \
  --no-profile \
  --flavor DummyTarget \
  && echo "✅ [1/9] Debug build SUCCESS" \
  || echo "❌ [1/9] Debug build FAILED — check Flutter output above"
Note: Flutter 3.24+ may show a "FileSystemException: Deletion failed, Directory not empty" crash at the end. This is a known Flutter bug — the build still succeeds. Check that build/ios/framework/Debug/App.xcframework exists before continuing.

Output location: build/ios/framework/Debug/

2
Build Release Flutter Frameworks (Real Device slice)
REQUIRED

Produces AOT-compiled device binaries and all plugin xcframeworks. This is the primary build.

# [2/9] Build Release Flutter frameworks
echo "=== [2/9] Building Release Flutter frameworks ==="

cd /Users/salespanda/rahul_work_space/sp-sdk/flutter-new-sdk

flutter build ios-framework \
  --no-debug \
  --no-profile \
  --flavor DummyTarget \
  && echo "✅ [2/9] Release build SUCCESS" \
  || echo "❌ [2/9] Release build FAILED — check Flutter output above"
Note: Same FileSystemException may appear — same fix (check output exists, continue).

Output location: build/ios/framework/Release/

3
Copy Release Frameworks to SDK (skip App.xcframework)
REQUIRED

Copies all xcframeworks from the Release build into the SDK Frameworks/ folder. Skips App.xcframework — that is handled separately in Step 4.

# [3/9] Copy Release frameworks (skip App.xcframework)
echo "=== [3/9] Copying Release frameworks ==="

RELEASE_DIR="/Users/salespanda/rahul_work_space/sp-sdk/flutter-new-sdk/build/ios/framework/Release"
SDK_FRAMES="/Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration/Frameworks"

for xcfw in "$RELEASE_DIR"/*.xcframework; do
  name=$(basename "$xcfw")

  if [ "$name" = "App.xcframework" ]; then
    echo "  → Skipping App.xcframework (handled in Step 4)"
    continue
  fi

  rm -rf "$SDK_FRAMES/$name" \
    && cp -R "$xcfw" "$SDK_FRAMES/$name" \
    && echo "  ✅ Copied: $name" \
    || echo "  ❌ FAILED: $name"
done

echo "✅ [3/9] Release frameworks copy complete"
Important: Always rm -rf the destination before cp -R. If you skip this, cp -R will merge into the old folder instead of replacing it, causing corrupted xcframeworks.
4
Create Mixed App.xcframework (Device from Release + Simulator from Debug)
REQUIRED

The Flutter engine in Release mode (AOT) needs an AOT App binary for the device, and the Debug engine needs a kernel_blob.bin for the simulator. We combine both into one xcframework.

# [4/9] Create mixed App.xcframework
echo "=== [4/9] Creating mixed App.xcframework ==="

RELEASE_DIR="/Users/salespanda/rahul_work_space/sp-sdk/flutter-new-sdk/build/ios/framework/Release"
DEBUG_DIR="/Users/salespanda/rahul_work_space/sp-sdk/flutter-new-sdk/build/ios/framework/Debug"
SDK_FRAMES="/Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration/Frameworks"

# Verify both slices exist before proceeding
DEVICE_FW="$RELEASE_DIR/App.xcframework/ios-arm64/App.framework"
SIM_FW="$DEBUG_DIR/App.xcframework/ios-arm64_x86_64-simulator/App.framework"

if [ ! -d "$DEVICE_FW" ]; then
  echo "❌ [4/9] Device framework missing: $DEVICE_FW"
  echo "   Did Step 2 (Release build) complete successfully?"
  exit 1
fi

if [ ! -d "$SIM_FW" ]; then
  echo "❌ [4/9] Simulator framework missing: $SIM_FW"
  echo "   Did Step 1 (Debug build) complete successfully?"
  exit 1
fi

TMPDIR_APP=$(mktemp -d /tmp/app_mix_XXXX)

# Copy device slice (Release AOT — ~15 MB binary)
cp -R "$DEVICE_FW" "$TMPDIR_APP/device_fw" \
  && echo "  ✅ Device framework copied (Release AOT)" \
  || { echo "  ❌ Failed to copy device framework"; rm -rf "$TMPDIR_APP"; exit 1; }

# Copy simulator slice (Debug — contains kernel_blob.bin, ~84 KB)
cp -R "$SIM_FW" "$TMPDIR_APP/sim_fw" \
  && echo "  ✅ Simulator framework copied (Debug)" \
  || { echo "  ❌ Failed to copy simulator framework"; rm -rf "$TMPDIR_APP"; exit 1; }

# Remove old App.xcframework and build the mixed one
rm -rf "$SDK_FRAMES/App.xcframework"

xcodebuild -create-xcframework \
  -framework "$TMPDIR_APP/device_fw" \
  -framework "$TMPDIR_APP/sim_fw" \
  -output "$SDK_FRAMES/App.xcframework" \
  && echo "✅ [4/9] Mixed App.xcframework created" \
  || echo "❌ [4/9] Failed to create mixed App.xcframework"

rm -rf "$TMPDIR_APP"
Why mixed? Device slice uses AOT (Ahead-Of-Time compiled Dart VM snapshot, ~15 MB). Simulator slice uses JIT (kernel_blob.bin, ~84 KB). Mixing the wrong mode causes "VM snapshot invalid / Could not create Dart VM instance" crash on device.
5
Run fix_simulator_frameworks.sh
REQUIRED

The Release build only produces an x86_64 simulator slice for FFmpeg. This script adds the arm64 simulator slice so Apple Silicon Macs can run the simulator. It also rebuilds libffmpegkit_stub.xcframework.

# [5/9] Fix FFmpeg simulator slice and rebuild libffmpegkit_stub
echo "=== [5/9] Running fix_simulator_frameworks.sh ==="

cd /Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration

./fix_simulator_frameworks.sh \
  && echo "✅ [5/9] Simulator fix complete" \
  || echo "❌ [5/9] Simulator fix FAILED — see output above"
What this script does internally:
  1. Checks if ffmpeg_kit_flutter_new.xcframework already has arm64 simulator — skips if yes
  2. Compiles arm64 simulator stub from Sources/ffmpegkit_stub/ffmpegkit_stub.m
  3. Lipo-combines with existing x86_64 binary to create fat simulator binary
  4. Rebuilds xcframework with device + fat simulator slices
  5. Rebuilds libffmpegkit_stub.xcframework (device + simulator)

Update SDK Version in Podspec
REQUIRED

Bump the version number in MyPrivateSDK.podspec. Use semantic versioning: MAJOR.MINOR.PATCH

# [6/9] Open podspec and update version
echo "=== [6/9] Current version ==="
grep "s.version" /Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration/MyPrivateSDK.podspec

# Edit the file — change the version line:
#   s.version = '2.0.5.1'   →   s.version = '2.0.6'   (example)

open /Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration/MyPrivateSDK.podspec
Version guide: Patch (2.0.5 → 2.0.6) for bug fixes or minor framework updates. Minor (2.0.x → 2.1.0) for new features. Major (2.x → 3.0) for breaking changes.

After editing, verify the change:

grep "s.version" /Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration/MyPrivateSDK.podspec

  && echo "✅ Clean pod install SUCCESS" \

Test checklist before proceeding to Step 8:

  • App builds and runs on iOS Simulator (Debug)
  • Flutter screen loads without crash
  • App builds and runs on Real Device (Debug)
  • App builds on Real Device (Release) — via Xcode → Product → Archive
  • No "VM snapshot invalid" crash on real device
  • No "Command GenerateDSYMFile failed" error
8
Commit, Tag and Push to GitHub
REQUIRED

Replace NEW_VERSION with the version number from Step 6 (e.g. 2.0.6).

# [8/9] Commit and push to GitHub
echo "=== [8/9] Committing and tagging SDK ==="

# ⬇ SET YOUR VERSION HERE
NEW_VERSION="2.0.6"

cd /Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration

# Stage framework files and podspec
git add Frameworks/ Libraries/ MyPrivateSDK.podspec \
  && echo "  ✅ Files staged" \
  || { echo "  ❌ git add FAILED"; exit 1; }

# Commit
git commit -m "Release SDK $NEW_VERSION" \
  && echo "  ✅ Committed" \
  || { echo "  ❌ git commit FAILED"; exit 1; }

# Create tag
git tag "$NEW_VERSION" \
  && echo "  ✅ Tag $NEW_VERSION created" \
  || { echo "  ❌ git tag FAILED"; exit 1; }

# Push branch
git push origin main \
  && echo "  ✅ Branch pushed" \
  || { echo "  ❌ Branch push FAILED"; exit 1; }

# Push tag
git push origin "$NEW_VERSION" \
  && echo "✅ [8/9] Tag $NEW_VERSION pushed to GitHub" \
  || echo "❌ [8/9] Tag push FAILED"
Verify on GitHub: Go to github.com/rpgh23/Flutter-React-Integration/tags and confirm the new tag appears before telling the client.

Troubleshooting
Error Cause Fix
VM snapshot invalid / Could not create Dart VM instance Release Flutter engine (device) paired with Debug App.xcframework (simulator slice) Redo Step 4 — mixed App.xcframework must have Release device + Debug simulator slices
Command GenerateDSYMFile failed Release App.xcframework binary has no debug symbols; dsymutil fails Podspec must have s.user_target_xcconfig = { 'DEBUG_INFORMATION_FORMAT[config=Debug]' => 'dwarf' } — already in 2.0.5+
Command PhaseScriptExecution failed / No space left on device Disk is full during xcframework copy (~50 frameworks) Free disk space: delete DerivedData (~/Library/Developer/Xcode/DerivedData) and CocoaPods cache (~/Library/Caches/CocoaPods)
App_mixed.xcframework inside App.xcframework (nested) cp -R source dest when dest exists merges instead of replacing Always rm -rf dest before cp -R source dest
facebook::react::Sealable undefined symbols Stale DerivedData codegen conflicts with React Native prebuilt libs Full clean: remove DerivedData + Pods + Podfile.lock, then fresh pod install
fix_simulator_frameworks.sh: No such file or directory Script targets wrong filename or xcframework not found Confirm Frameworks/ffmpeg_kit_flutter_new.xcframework exists (Step 3 must run first)
Simulator works, real device crashes App.xcframework device slice is Debug (not AOT) Step 4 — ensure device slice comes from Release/App.xcframework/ios-arm64/
arm64 simulator fails (Apple Silicon Mac) FFmpeg xcframework only has x86_64 simulator slice after Release build Run Step 5 (fix_simulator_frameworks.sh) after every framework update
Facebook SDK Integration Note
Facebook App ID goes in the HOST app — not in the SDK.

The SDK depends on FBSDKCoreKit/LoginKit/ShareKit (already in podspec). The client app must add to their Info.plist: 
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLSchemes</key>
    <array><string>fb<YOUR_APP_ID></string></array>
  </dict>
</array>
<key>FacebookAppID</key><string><YOUR_APP_ID></string>
<key>FacebookClientToken</key><string><YOUR_CLIENT_TOKEN></string>
<key>FacebookDisplayName</key><string><YOUR_APP_NAME></string>
No changes needed in the SDK itself for different clients.
Quick Reference — Commands Only
All 9 steps as a single script (run from Terminal)
Edit the two variables at the top before running: NEW_VERSION and FLUTTER_PROJECT
#!/bin/bash
# SDK Update Script — edit variables below before running

NEW_VERSION="2.0.6"
FLUTTER_PROJECT="/Users/salespanda/rahul_work_space/sp-sdk/flutter-new-sdk"
SDK_DIR="/Users/salespanda/rahul_work_space/React-SDK/Flutter-React-Integration"
SDK_FRAMES="$SDK_DIR/Frameworks"
RN_IOS="/Users/salespanda/rahul_work_space/ReactIOS/ios"

# ── Step 1: Debug build ────────────────────────────────────
echo "=== [1/9] Debug build ==="
cd "$FLUTTER_PROJECT"
flutter build ios-framework --no-release --no-profile --flavor DummyTarget \
  && echo "✅ [1/9] Debug build SUCCESS" || echo "❌ [1/9] Debug build FAILED"

# ── Step 2: Release build ──────────────────────────────────
echo "=== [2/9] Release build ==="
flutter build ios-framework --no-debug --no-profile --flavor DummyTarget \
  && echo "✅ [2/9] Release build SUCCESS" || echo "❌ [2/9] Release build FAILED"

# ── Step 3: Copy Release frameworks ───────────────────────
echo "=== [3/9] Copy Release frameworks ==="
for xcfw in "$FLUTTER_PROJECT/build/ios/framework/Release"/*.xcframework; do
  name=$(basename "$xcfw")
  [ "$name" = "App.xcframework" ] && echo "  → Skip App.xcframework" && continue
  rm -rf "$SDK_FRAMES/$name" && cp -R "$xcfw" "$SDK_FRAMES/$name" \
    && echo "  ✅ $name" || echo "  ❌ $name"
done
echo "✅ [3/9] Done"

# ── Step 4: Mixed App.xcframework ─────────────────────────
echo "=== [4/9] Mixed App.xcframework ==="
TMPDIR_APP=$(mktemp -d /tmp/app_mix_XXXX)
cp -R "$FLUTTER_PROJECT/build/ios/framework/Release/App.xcframework/ios-arm64/App.framework" "$TMPDIR_APP/device_fw" \
  && echo "  ✅ Device slice copied" || { echo "  ❌ Device slice FAILED"; exit 1; }
cp -R "$FLUTTER_PROJECT/build/ios/framework/Debug/App.xcframework/ios-arm64_x86_64-simulator/App.framework" "$TMPDIR_APP/sim_fw" \
  && echo "  ✅ Simulator slice copied" || { echo "  ❌ Simulator slice FAILED"; exit 1; }
rm -rf "$SDK_FRAMES/App.xcframework"
xcodebuild -create-xcframework \
  -framework "$TMPDIR_APP/device_fw" \
  -framework "$TMPDIR_APP/sim_fw" \
  -output "$SDK_FRAMES/App.xcframework" \
  && echo "✅ [4/9] Mixed App.xcframework created" || echo "❌ [4/9] FAILED"
rm -rf "$TMPDIR_APP"

# ── Step 5: Fix FFmpeg simulator slice ────────────────────
echo "=== [5/9] Fix FFmpeg simulator slice ==="
cd "$SDK_DIR"
./fix_simulator_frameworks.sh \
  && echo "✅ [5/9] FFmpeg fix done" || echo "❌ [5/9] FFmpeg fix FAILED"

# ── Step 6: Bump version ───────────────────────────────────
echo "=== [6/9] Bump version in podspec ==="
sed -i '' "s/s.version      = '.*/s.version      = '$NEW_VERSION'/" "$SDK_DIR/MyPrivateSDK.podspec"
grep "s.version" "$SDK_DIR/MyPrivateSDK.podspec" \
  && echo "✅ [6/9] Version updated to $NEW_VERSION" || echo "❌ [6/9] Version update FAILED"

# ── Step 7: pod install (local path test) ─────────────────
echo "=== [7/9] pod install (make sure Podfile uses :path) ==="
cd "$RN_IOS"
pod install \
  && echo "✅ [7/9] pod install SUCCESS" || echo "❌ [7/9] pod install FAILED"

echo "⚠️  TEST THE APP ON SIMULATOR AND REAL DEVICE NOW. Continue to Step 8 only if tests pass."
echo "   Press Enter to continue to git push, or Ctrl+C to abort."
read

# ── Step 8: Commit, tag, push ─────────────────────────────
echo "=== [8/9] Commit, tag, push ==="
cd "$SDK_DIR"
git add Frameworks/ Libraries/ MyPrivateSDK.podspec \
  && echo "  ✅ Files staged" || { echo "  ❌ git add FAILED"; exit 1; }
git commit -m "Release SDK $NEW_VERSION" \
  && echo "  ✅ Committed" || { echo "  ❌ git commit FAILED"; exit 1; }
git tag "$NEW_VERSION" \
  && echo "  ✅ Tag $NEW_VERSION created" || { echo "  ❌ git tag FAILED"; exit 1; }
git push origin main \
  && echo "  ✅ Branch pushed" || { echo "  ❌ Branch push FAILED"; exit 1; }
git push origin "$NEW_VERSION" \
  && echo "✅ [8/9] Tag $NEW_VERSION pushed to GitHub" || echo "❌ [8/9] Tag push FAILED"

echo ""
echo "🎉 SDK $NEW_VERSION released!"
echo "   Update Podfile :tag => to '$NEW_VERSION' and run pod install (Step 9)"
